## ① モンスターデータの取り込み

### やりたいこと

いまアプリが持っているのは **種族（純血種）38種だけ**。ここに **派生種** も入れて、
「種族を選ぶ → 派生種を選ぶ」だけで、育成計算タブの基本設定が自動で埋まるようにする。

派生種ごとに決まっている値：

7項目はすべて **モンスタータブ** に集めてある。

| 項目 | いまの入力欄 |
|---|---|
| 寿命 | モンスタータブ「成長設定 > 寿命」 |
| 成長タイプ | モンスタータブ「成長設定 > 成長タイプ」（早熟 / 持続 / 普通 / 晩成） |
| ヨイワル | モンスタータブ「成長設定 > ヨイワル」 |
| 成長適正（6種 E〜A） | モンスタータブ「各パラメータの成長適正」 |
| 初期パラメーター（6種） | モンスタータブ「初期パラメーター」 |
| ガッツ回復 | モンスタータブ「ガッツ回復速度」 |

いまは全部を毎回手で入れているので、そこが丸ごと不要になる。
入力欄が1画面にまとまっているので、「派生種を選ぶ」プルダウンもこの画面に置けばよい。

### 大変なところ

**派生種は全部で400種を超える。** 上の7項目 × 400種以上をデータとして持つことになり、
その入力がほぼ手作業になる。ここが一番の山。

### 現状のコードとの関係

- 種族の一覧は `js/data/monsters.js`（技データ）が事実上の名簿になっている。
  派生種は技データを持たないので、**名簿を技データから切り離す**必要がある。
- 個体の値は `js/store.js` の `defaultSim()`（と `defaultMon().guts`）が初期値を持っている。
  派生種を選んだら、そこへ流し込む形になる。画面は `js/monster.js`。
- 種族の選択は `js/species.js` にまとまっていて、選び直すと `species:change` が飛ぶ。
  派生種の選択もここに乗せるのが自然。
- 保存データは **種族名がキー**。派生種を足すときも、既存の種族名は絶対に変えないこと。

### 決めていないこと

- 派生種ごとに記録を分けるのか、純血種でまとめるのか（保存データの持ち方が変わる）
- 400種ぶんのデータをどこから、どうやって入れるか（手入力 / 表からの変換 / 段階的に足す）
- 全部入れるとファイルが重くなるので、アイコンと同じように遅延読み込みにするか

### 決まっていること（確認ずみ）

**内部数値の範囲**（生まれた直後の値はヨイワル以外すべて 0）

※ 調整ローテの「開始時点の初期値」（体型-100 / 恐れ度100 / 甘え度100 など）は
これとは別もの。生まれた直後ではなく、調整ローテを始める時点の想定値。
コード上も `INNER.init`（生まれた直後）と `defaultRota().start`（調整ローテの開始時点）で
分けてある。

| 内部数値 | 範囲 |
|---|---|
| 疲労 / ストレス / 恐れ度 / 甘え度 / 人気 | 0 〜 100 |
| 体型 | -100 〜 100 |
| ヨイワル | -100 〜 100 |

ヨイワルだけは初期値がモンスターごとに違い、さらに **初期値から±100までしか動かない**。
初期値 -90 のモンスターなら -100〜+10 が動ける範囲（`moralRange()`）。
基本設定の入力欄も -100〜100 を5きざみで選ぶ形にした。

**計算の決まりごと**

- ゲーム内の計算は、途中で小数点以下を切り捨てる。
  「ストレス-50%」のような割合は、**割合を出した時点で切り捨て、そのあとで足し引き**する
  （ストレス75なら 37.5→37 を引いて 38。`pctDelta()`）。
- 寿命の増減は、**寿命そのものが減るのではなく、そのぶん歳を取る**（週が進む）。
  データでは `agePlus`（進む週数）として持っている。
- 1週間に **アイテム1個と行動1回の両方** ができる。アイテムは与えなくてもよい。
- イベントは、**減る寿命と実際に進む週数が違う**。

  | イベント | 寿命 | 進む週 |
  |---|---|---|
  | 大会 | -4 | 1週 |
  | 修行 | -7 | 4週 |
  | 冒険 | -2 | 4週 |

  `js/data/growth.js` の `EV_COST`（寿命）と `EV_WEEKS`（進む週）。
  育成計画の割当週から引いているのは `EV_COST` のほう。
- 寿命の消費が段階の週数を超えたら、**はみ出たぶんは次の段階から引く**。
  例: 1段階10週にパラドクシン(-18)を使うと 1段階のトレーニングは0週になり、
  次の段階が8週ぶん短くなる。
- アイテムには2種類ある。
  - 使うと無くなるもの（`kind:'use'`）… 16件のうち15件
  - 持っているだけで効くもの（`kind:'hold'`）… 双子の水差し。
    月初めに効果がかかり、**持っている数だけ重なる**（3個なら ストレス-3 / 恐れ度+3）
- 効果の続くもの（トロロン・パラドクシン）は、**その週数をかけて上がり、そのあとも残る**。
  パラドクシンの「回避と丈夫さ-10%」は、その4週のあいだ毎週、そのときの値に対してかかる。
- 種族条件つきの効果はその効果だけにかかる。
  オイリーオイルの疲労-28 / 恐れ度+1 / 甘え度+1 は全種族、ストレス-20% だけが
  デュラハン・アローヘッド・ヘンガー限定。

### 改良案：寿命が減るアイテムのセットを自動で作る

まだ着手していない案。実際の使い方はこうなる（パラドクシン・トロロン）。

```
 ○月1週  パラドクシンを使う → その月は4回トレーニング
 翌月1週  2個目を使う       → その月も4回トレーニング
 以下同様
```

これを育成計画の形に直すと、1個ぶんが2つのセットになる。

| | 割当週 | 中身 | トレ | 暦 |
|---|---|---|---|---|
| スルー用のセット | 18（＝寿命の減少分） | パラドクシン1個 | 0週 | 0週 |
| トレーニングのセット | 4 | 重トレ/軽トレ | 4週 | 4週 |

寿命は22週進むが、暦は4週（1か月）しか進まない。これを個数ぶん繰り返す。

**いまの作りでも、この形は手で組める。** そして「18＋4のセットを4組」と
「88週のセット1つにパラドクシン4個」は、寿命・暦・トレーニング週・上昇値が
すべて一致することを確かめてある（`js/simulator/growth-calc.js` の計算どおり）。
なので合計だけ見るなら今のままでよく、改良の中身は次の2点になる。

- セットを手で8つ作る手間をなくす（個数を入れたら、その組を自動で並べる）
- 「スルー → その月にトレーニング」という並び順が画面に出るので、
  月ごとの流れが見えるようになる。薬を使った月だけトレーニングを変える、
  といった組み方もできる

決めていないこと:

- 自動で組んだセットを、あとから手で直せるようにするか
- 割当週が「（寿命の減少分＋4）×個数」で割り切れないときの端数をどうするか
- トロロン（-6）だと1個ぶんが 6＋4＝10週。この形でよいか

### 役割の分け方

### やりたいこと

アイテム・トレーニング・休養といった **行動ごとの数値をアプリに覚えさせて**、
「いつ何をしたら内部数値がどうなるか」を追えるようにする。

入力のイメージ：

```
 4月1週  トレーニング：重り引き
 4月2週  アイテム：まずいマタタビ
 4月3週  休養
 4月4週  大会
 …（3か月ぶんくらい）
```

これを並べて、各タイミングの **体調値** を計算し、最終的な細かい数値を自動で出す。

### 大変なところ

計算そのものは、アイテムと行動による内部数値の変化がおおよそ決まっているので、たぶん重くない。
**アプリに覚えさせる情報の量**（アイテム一覧とその効果、行動ごとの変化）が多いのが本番。

### 現状のコードとの関係

- 育成計画は **段階ごとにまとめて計算**する作り（`js/simulator/growth-calc.js`）。
  週ごとのシミュレートは粒度が違うので、**別の計算ファイル**として足すのがよさそう。
  `growth-calc.js` と同じく、画面に依存しない純粋な計算にしておけば Node だけでテストできる。
- **開始時期（月・週）** の入力欄は育成計画のいちばん上にある。
  いまは段階が始まる時期（○月◎週）の計算に使っていて、週ごとのシミュレートの起点にもなる。
- 画面は `js/simulator/rotation.js`（いまは案内文だけ）。`#rotationArea` に描く。
  保存先はまだ決めていないが、種族ごとなら `mon.sim` の下、
  期間を複数持つなら配列にすることになる。
