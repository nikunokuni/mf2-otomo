# 全種族の技データ（実装の検討）

「**全種族の技データを保存して、アプリ内で確認できるようにしたい**」の検討メモ。
まだ実装していない。ここで形を決めてから手を動かす。

`docs/events-and-skills.md` の ④ で「全技の一覧は @wiki を見てもらう方針（取り込みは見送り）」と
書いたぶんを、**取り込む方向にひっくり返す**話になる。見送った理由は入力量だったので、
そこをどう分けて進めるかが本題。

---

## 1. いま持っているもの / 持っていないもの

| | 中身 | ファイル |
|---|---|---|
| 持っている | **使い込みで上位技に変わるペアだけ**（38種で201ペア） | `js/data/monsters.js` |
| 持っていない | 最初から持っている技 / 修行で覚える技 / 技そのものの性能 / 習得条件 | — |

`monsters.js` の1件はこうなっている。

```js
{ from:"タッチ", to:"はり手", need:30, guts:12, hit:3.8, miss:3.8 }
```

ここで大事なのは **`guts` / `hit` / `miss` は下位技（`from`）のもの**だということ。
使い込みは下位技を撃ち続ける行為なので、理想使用回数の計算（`js/tracker/ideal.js`）にも
下位技の消費ガッツとモーション秒を渡している。
つまり `monsters.js` は、すでに **「201技ぶんの性能表」を部分的に持っている**。

また、種族の名簿そのものが `Object.keys(MONSTER_DATA)` になっている（`js/species.js`）。
技を持たない種族（ライガー / スエゾー / ジョーカー）は空配列 `[]` で名簿にだけ載っている。

## 2. データの置き場と形

### `js/data/moves.js` を新しく作る。`monsters.js` は触らない

**理由：`monsters.js` の `from→to` は保存データのキー**（`techKey()`）。
作り直すと使い込みの記録が丸ごと迷子になる。技名を1文字直すだけでも同じことが起きる。
新しい名簿を別ファイルに置き、**技名で突き合わせる**のが安全。

将来 `monsters.js` を `moves.js` から組み立て直すことはできるが、
そのときも **キーの文字列は今のまま**にする、という制約だけ守ればよい。

### 1種族ぶんの形

```js
export const MOVES = {
  ピクシー: [
    { name:'タッチ',   dist:1, guts:12, type:'pow', power:30, hitRate:20, crit:5,
      hit:3.8, miss:3.8, learn:'init' },

    { name:'はり手',   dist:1, guts:18, type:'pow', power:45, hitRate:10, crit:5,
      hit:4.1, miss:3.8, learn:{ kind:'use', from:'タッチ', need:30 } },

    { name:'ヒールレイド', dist:2, guts:19, type:'pow', power:60, hitRate:-5, crit:10,
      hit:3.3, miss:4.3,
      learn:{ kind:'trip', place:'火山' },
      req:{ stats:{ pow:150 }, moral:[-100,-50] } },
  ],
};
```

| キー | 中身 | 備考 |
|---|---|---|
| `name` | 技名 | **@wiki の表記に合わせる。`monsters.js` の技名と1文字も違わないこと** |
| `dist` | 使う間合い（1〜4） | |
| `guts` | 消費ガッツ | `monsters.js` の `guts` と同じ値になる（下位技のぶん） |
| `type` | `'pow'` ちから技 / `'int'` かしこさ技 | |
| `power` | ダメージ | ★列名と単位は表を見て確定する |
| `hitRate` | 命中補正 | ★同上 |
| `crit` | クリティカル率 | ★同上 |
| `hit` / `miss` | 命中時・空振り時のモーション秒 | `monsters.js` と同じ値になる |
| `learn` | 覚え方（下記） | |
| `req` | 習得条件（下記） | 無ければ省略 |
| `note` | 補足（自由文） | 無ければ省略 |

★を付けた3つは、いまアプリが持っていない値。**@wiki の表の列名をそのまま写す形にしたい**ので、
実物の1種族ぶんを見せてもらってから確定する（列が足りなければ足す。増やすのは後からでもできる）。

### `learn`（覚え方）

| 書き方 | 意味 |
|---|---|
| `'init'` | 最初から持っている |
| `{ kind:'use', from:'タッチ', need:30 }` | 使い込みで覚える。`from` は `monsters.js` と同じ技名 |
| `{ kind:'trip', place:'火山' }` | 修行で覚える |
| `{ kind:'other', note:'…' }` | それ以外（合体で引き継ぐ、など） |

### `req`（習得条件）

```js
req: { stats:{ pow:150, int:120 }, moral:[-100,-50] }
```

- `stats` … パラメータのしきい値。キーは `js/data/growth.js` の `SK` と同じ並びを使う
- `moral` … ヨイワルの範囲 `[下限, 上限]`。
  ヨイワルは**初期値から±100までしか動かない**（`moralRange()`）ので、
  種族によっては**そもそも届かない技**が出る。そこは画面で「この種族では条件外」と出せる。

**条件は後から足せる形にしておく**（`req` が無い技＝条件を調べていない技、として扱う）。
1段階目は名前と性能だけ、条件は2段階目、という分け方ができる。

### `monsters.js` との重なりをどうするか

`guts` / `hit` / `miss` は両方のファイルに載る。**消さずに両方持ち、テストで一致を見る。**

- `monsters.js` は保存キーを持つ「動かせないファイル」。減らすと移行が必要になる
- `moves.js` は全技ぶんを持つので、下位技だけ値を抜くと**穴あきの表**になって使いにくい
- 代わりに `test/calc.test.mjs` で全ペアを回し、
  「`MONSTER_DATA[種族]` の `from` / `to` / `milestone.to` が `MOVES[種族]` に必ずあること」
  「`from` の `guts` / `hit` / `miss` が一致すること」を検証する。
  **技名のうっかりミスは、ここで全部落ちる**（`SPECIES_SPEC` のテストと同じやり方）

## 3. 画面（どこで確認するか）

置き場の決め方（README「開発するときに気をつけること」）に当てると、
技は **種族ごと** で **決まった値** なので、モンスター / 使い込み / 育成計算 の並びに入る。
早見タブ（種族に関係ない箱）ではない。

| 案 | 中身 | 良いところ | 困るところ |
|---|---|---|---|
| **A（推し）** | 使い込みタブを2階層にして **「使い込み / 技一覧」** に分ける | 上位タブは4つのまま。育成計算タブと同じ見た目・同じ作りを流用できる。一覧に画面を丸ごと使える | `js/tabs.js` の下位タブが育成計算タブ専用の作りなので、そこを一般化する必要がある |
| B | 使い込みタブの下に、たたんだカードを1枚足す | いちばん小さい変更。タブの仕組みを触らない | すでに縦に長いタブがさらに伸びる。一覧の表を横に広げにくい |
| C | 上位タブに「技」を足して5つにする | いちばん分かりやすい | `.tabbar__btn` は `flex:1` なので、幅390pxだと5つで1つ約74px。「モンスター」がはみ出す。**先にタブの見た目を作り直すことになる** |

**A を推す。** 理由は、いずれ `docs/events-and-skills.md` ④ に書いた
「**技を選ぶ → 育成計画が決まる**」につなげたいから。そのときは技を選ぶ操作が要るので、
たたんだカード（B）では手狭になる。最初から独立した画面にしておきたい。

### A の画面イメージ

```
[使い込み] [技一覧]        ← 下位タブ（育成計算タブと同じ見た目）

  ▼ 絞り込み： [ぜんぶ] [最初から] [使い込み] [修行]
  ┌──────────────────────────────────────┐
  │ 技名        間合 消費G ダメージ 命中 クリ 覚え方 │
  │ タッチ       1    12    30     20   5   最初から│
  │ はり手       1    18    45     10   5   使い込み│  ← タッチ→30回
  │ ヒールレイド  2    19    60     -5  10   修行(火山)│  ← ちから150 / ワル寄り
  └──────────────────────────────────────┘
```

- 表そのものは `class="table"` を `.scroll-x` で包むだけ（使い込みタブと同じ作りでよい）
- 覚え方で色分けし、条件つきの技は行の下に条件を small で出す
- 習得条件（`req`）が入ったら、**モンスタータブの初期ヨイワルから届かない技をグレーにする**
  ところまでは、計算を足さずにできる

### 種族の名簿について

いま名簿は `MONSTER_DATA` から作っている。`moves.js` を足しても**当面はそのまま**でよい
（38種は両方に載るので）。派生種を足すとき（`docs/roadmap.md` ①）に名簿を切り離す話が
出てくるので、そのときまとめて直す。ここでは触らない。

## 4. 読み込み方

ざっくりの見積り：**38種 × 10〜20技 ≒ 400〜500技**、1技あたり100バイト前後で **50KB前後**。
アイコン（`js/data/icons.js`、40KB）と同じくらい。

なので **アイコンと同じ遅延読み込み**にする。

```js
// 技一覧を最初に開いたときだけ取りに行く
import('../data/moves.js').then((m) => m.MOVES)
```

起動が重くならないし、技一覧を見ない人は読み込まない。
`js/species.js` の `loadIcons()` がそのまま手本になる。

## 6. 進め方

| 段階 | 中身 | 分量 |
|---|---|---|
| ① | 形を決めて、**1種族ぶん（ピクシー）だけ**入れて画面とテストを通す | 小 |
| ② | 残り37種を **1種族ずつ**足す（`SPECIES_SPEC` と同じやり方。1コミット1種族） | 大。データ次第 |
| ③ | 習得条件（`req`）を足して、届かない技をグレーにする | 中 |
| ④ | 技を選ぶ → 育成計画へ（修行回数・目標ステータス・ヨイワルの順番） | 別の検討 |

**①をやってから②に入る**のが大事で、形が決まる前に400技を入れると、
列を足すたびに全部書き直すことになる。

テストは `SPECIES_SPEC` と同じく **`MOVES` を読んで全種族ぶんを自動でまわす**ので、
種族を足すときにテストを書き足す必要はない。

## 7. データの集め方（ここが本番）

@wiki は**このリポジトリの実行環境からは取りに行けない**（ネットワークが塞がれている）ので、
**中身を渡してもらう**形になる。1種族ぶんずつ、下のどれかで貼ってもらえれば変換できる。

- @wiki の表をそのままコピペ（タブ区切りになる）
- 手打ちなら `技名 / 間合 / 消費G / ダメージ / 命中 / クリ / 覚え方` の順で1行1技

```
ピクシー
タッチ	1	12	30	20	5	最初から
はり手	1	18	45	10	5	使い込み タッチ 30
ヒールレイド	2	19	60	-5	10	修行 火山
```

列がこれで足りるか（＝@wiki に何の列があるか）は、**1種族ぶん見せてもらえれば確定できる**。

## 8. 決めていないこと

- ★の3列（ダメージ / 命中 / クリティカル）の正確な列名と単位
- 命中時に相手のガッツを削る量・外したときに自分が失うガッツを持つか（表にあるなら持ちたい）
- 派生種で覚える技が変わるか（変わるなら名簿は派生種ごと。`docs/roadmap.md` ① と同じ問題）
- 「覚えた技」をユーザーが記録できるようにするか（するなら `state` に足す＝6の④）
- A案（下位タブ）でよいか
