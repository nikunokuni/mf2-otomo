# 全種族の技データ（実装の検討）

「**全種族の技データを保存して、アプリ内で確認できるようにしたい**」の検討メモ。

> **① 済。② 進行中（2/38種）。**@wiki の技一覧を画像で見せてもらう形で、
> 1種族ずつ `js/data/moves.js` に足している。
> 画面は使い込みタブのいちばん下の「この種族が覚える技」（`js/tracker/moves.js`）。
> `monsters.js` との突き合わせテストが、写し間違いを自動で拾う。
>
> | 済 | 技数 | `monsters.js` との食い違い |
> |---|---|---|
> | ピクシー | 21 | 1件（ヒールレイド。@wiki が正しく、`monsters.js` を直した） |
> | ドラゴン | 19 | なし（7ペア×4か所すべて一致） |

`docs/events-and-skills.md` の ④ で「全技の一覧は @wiki を見てもらう方針（取り込みは見送り）」と
書いたぶんを、**取り込む方向にひっくり返す**話になる。見送った理由は入力量だったので、
そこをどう分けて進めるかが本題。

---

## 1. いま持っているもの / 持っていないもの

| | 中身 | ファイル |
|---|---|---|
| 持っている | **使い込みで上位技に変わるペアだけ**（38種で201ペア） | `js/data/monsters.js` |
| 持っていない | 最初から持っている技 / 修行で覚える技 / 技そのものの性能 / 習得条件 | — |

`monsters.js` の1件はこうなっている。

```js
{ from:"タッチ", to:"はり手", need:30, guts:12, hit:3.8, miss:3.8 }
```

ここで大事なのは **`guts` / `hit` / `miss` は下位技（`from`）のもの**だということ。
使い込みは下位技を撃ち続ける行為なので、理想使用回数の計算（`js/tracker/ideal.js`）にも
下位技の消費ガッツとモーション秒を渡している。
つまり `monsters.js` は、すでに **「201技ぶんの性能表」を部分的に持っている**。

また、種族の名簿そのものが `Object.keys(MONSTER_DATA)` になっている（`js/species.js`）。
技を持たない種族（ライガー / スエゾー / ジョーカー）は空配列 `[]` で名簿にだけ載っている。

## 2. データの置き場と形

### `js/data/moves.js` を新しく作る。`monsters.js` は触らない

**理由：`monsters.js` の `from→to` は保存データのキー**（`techKey()`）。
作り直すと使い込みの記録が丸ごと迷子になる。技名を1文字直すだけでも同じことが起きる。
新しい名簿を別ファイルに置き、**技名で突き合わせる**のが安全。

将来 `monsters.js` を `moves.js` から組み立て直すことはできるが、
そのときも **キーの文字列は今のまま**にする、という制約だけ守ればよい。

### 1種族ぶんの形（@wiki の表の列に合わせて確定）

@wiki の表は「アイコン / 技名 / 種類 / 遠←距離→近 / 消費G / ダメージ / 命中 / GD / CR /
ヨイワル / 備考 / 当時間 / 外時間 / 移動(当) / 移動(外) / 連射」の16列。
アイコン以外の15列に、**技名セルの地色**（列ではないが情報を持っている。下記）を足して持つ。

```js
export const MOVES = {
  ピクシー: [
    { name:'タッチ', stat:'pow', kind:'バランス', dist:1, guts:12, dmg:['E',6], acc:['A',10],
      gd:null, cr:null, moral:null, note:'',
      tHit:3.8, tMiss:3.8, mvHit:'1', mvMiss:'1→2', rapid:'強' },

    { name:'はり手', stat:'pow', kind:'バランス', dist:1, guts:18, dmg:['D',15], acc:['A',9],
      gd:['E',5], cr:null, moral:null, note:'タッチ30回',
      tHit:3.8, tMiss:4.1, mvHit:'1', mvMiss:'1→2', rapid:'並' },

    { name:'ドレイン', stat:'int', kind:'超必殺', dist:3, guts:40, dmg:['C',20], acc:['D',-10],
      gd:null, cr:null, moral:-50, note:'ライフドレイン率100%',
      tHit:3.1, tMiss:3.1, mvHit:'3', mvMiss:'3', rapid:'並' },
  ],
};
```

| キー | 表の列 | 中身 |
|---|---|---|
| `name` | 技名 | **`monsters.js` の技名と1文字も違わないこと** |
| `stat` | 技名セルの地色 | `'pow'` ちから技（黄 `#ffff00`）/ `'int'` かしこさ技（緑 `#008000`） |
| `kind` | 種類 | バランス / 大ダメージ / 超必殺 / 命中 / ガッツダウン / クリティカル |
| `dist` | 遠←距離→近 | 1=近 … 4=遠（数字が入っている列の位置と同じ数字） |
| `guts` | 消費G | `monsters.js` の `guts` と同じ値になる（下位技のぶん） |
| `dmg` | ダメージ | `E(6)` → `['E',6]`。空欄は `null` |
| `acc` | 命中 | 同上。マイナスもある |
| `gd` | GD | ガッツダウン。同上 |
| `cr` | CR | クリティカル率。同上 |
| `moral` | ヨイワル | `ワル(-50)` → `-50`、`ヨイ(+50)` → `50`。無ければ `null` |
| `note` | 備考 | **表の文字をそのまま**。使い込み条件・派生種固有・特殊効果が混ざっている |
| `tHit` / `tMiss` | 当時間 / 外時間 | `monsters.js` の `hit` / `miss` と同じ値になる |
| `mvHit` / `mvMiss` | 移動(当) / 移動(外) | `'2→2-3'` のような文字列。そのまま持つ |
| `rapid` | 連射 | 強 / 並 |
| `init` | 種類セルの淡い黄色 | 最初から持っている技なら `true`。**画面には出さない**（下記） |

アイコン列（ゲームのスプライト画像）は取り込まない。

### 技名セルの地色（列になっていない情報）

@wiki の表は、技名のセルを **黄 `#ffff00` と 緑 `#008000` の2色**で塗り分けている。
列が無いので見落としやすいが、**ちから技 / かしこさ技**の区別で、
どのパラメータでダメージが出るかという一番大事な属性にあたる。
ピクシーだと ちから8技 / かしこさ13技 で、近距離の技が黄・飛び道具が緑ときれいに割れる。

画像から実際の画素を読んで振り分けた（目で見て決めていない）。

### 色は「地の色と半々に混ぜて」使う

@wiki の色をそのまま塗ると、21行ぶん並んだときに発色が強すぎて表が読みにくい。
なので **もとの色と地の色をちょうど半分ずつ混ぜたもの**を塗っている
（＝不透明度50%で重ねたのと同じ見え方）。

```css
--rank-a-fill: color-mix(in srgb, var(--rank-a-bg) 50%, var(--color-background-primary));
```

- `opacity` ではなく「混ぜて不透明な色を作る」やり方にしたのは、
  **技名の列を左に貼り付けてある**（`position:sticky`）から。
  半透明にすると、下を流れていく他の列が透けて見えてしまう
- 混ぜる相手が地の色なので、**ダークでは自動的に暗いほうへ寄る**。
  ダークぶんの色を別に書く必要がない
- 濃さを変えたいときは `css/tokens.css` の `50%` だけを直せばよい
- `color-mix` が使えない環境では、もとの色がそのまま出る（`@supports` で分けてある）
- 薄めた地の上なので、ランクの文字色は本文と同じ1色で足りる。
  技名のセルだけ、ダークで緑が沈むので **かしこさ技の文字を明るく**している

### 種類セルの淡い黄色＝初期技

種類の列が、タッチとキックだけ淡い黄色 `#ffffa0` になっている。
この2つは**ピクシーが最初から持っている技**で、この読みで合っていることを確認ずみ。

**データには入れるが、画面には出さない。**（そう決めた）
色や印を足すと表がうるさくなるのに対して、いま欲しいのは「表をそのまま見る」ことなので、
出す理由がない。ただし ③（技を選んで育成計画につなぐ）では
「修行に何回行くか」を数えるのに **初期技かどうかが要る**ので、持っておく意味はある。

同じ考えで、**ちから技 / かしこさ技の見出しも画面には出していない**。
色が付いていれば区別は付くし、色の意味を知りたい人は @wiki を見る。

**習得条件を別のキーに分けるのはやめた。**@wiki は条件を備考欄の文章として持っていて
（「タッチ30回」「セピアリエーヴル固有」「ユキは修行で修得不可」）、形がそろっていない。
無理に構造化すると写し間違いが増えるので、**まずは文章のまま持って表示する**。
使い込み条件だけはテストで拾えるので、そこは自動で突き合わせている（下記）。

将来 ③（条件で技をしぼる）に進むときに、`req` を**足す**形で構造化すればよい。

### `monsters.js` との重なりをどうするか

`guts` / `hit` / `miss` は両方のファイルに載る。**消さずに両方持ち、テストで一致を見る。**

- `monsters.js` は保存キーを持つ「動かせないファイル」。減らすと移行が必要になる
- `moves.js` は全技ぶんを持つので、下位技だけ値を抜くと**穴あきの表**になって使いにくい
- 代わりに `test/calc.test.mjs` で全ペアを回し、
  「`MONSTER_DATA[種族]` の `from` / `to` / `milestone.to` が `MOVES[種族]` に必ずあること」
  「`from` の `guts` / `hit` / `miss` が一致すること」を検証する。
  **技名のうっかりミスは、ここで全部落ちる**（`SPECIES_SPEC` のテストと同じやり方）
- 使い込み回数は、上位技の備考にある「`<下位技><回数>回`」を正規表現で拾って
  `need` と突き合わせる。備考をそのまま持っていても、ここだけは自動で照合できる

**実装ずみ。そして、さっそく1件見つかった。**
ピクシーの ハイキック→ヒールレイド が `monsters.js` では `need:30`、
@wiki の備考では「ハイキック**50**回」。ほかの7ペア（消費G・当時間・外時間・回数）は
完全に一致していたので `monsters.js` 側の写し間違いで、**50回に直した**。

`need` は使い込みタブの「達成したかどうか」に使う値だが、**保存データのキーは
`下位技→上位技` のままなので記録は消えない**。すでに `done` が立っている記録も
そのまま（`done` は保存されている値で、`need` から計算し直していない）。
途中の記録は `30/30` が `30/50` の表示に変わる。

## 3. 画面（どこで確認するか）

置き場の決め方（README「開発するときに気をつけること」）に当てると、
技は **種族ごと** で **決まった値** なので、モンスター / 使い込み / 育成計算 の並びに入る。
早見タブ（種族に関係ない箱）ではない。

**決めた：B（使い込みタブの下に、たたんだカードを1枚足す）。**

| 案 | 中身 | 良いところ | 困るところ |
|---|---|---|---|
| **B（採用）** | 使い込みタブの下に、たたんだカードを1枚足す | いちばん小さい変更。タブの仕組みを触らない。すでにある畳み方をそのまま流用できる | すでに縦に長いタブがさらに伸びる。一覧の表を横に広げにくい |
| A | 使い込みタブを2階層にして「使い込み / 技一覧」に分ける | 一覧に画面を丸ごと使える | `js/tabs.js` の下位タブが育成計算タブ専用の作りなので、一般化が要る |
| C | 上位タブに「技」を足して5つにする | 分かりやすい | `.tabbar__btn` は `flex:1` なので、幅390pxだと5つで1つ約74px。「モンスター」がはみ出す。**先にタブの見た目を作り直すことになる** |

まずは「確認できる」ところまでなので、いちばん軽い形で入れる。
`docs/events-and-skills.md` ④ の「**技を選ぶ → 育成計画が決まる**」に進むときは、
そこで手狭になるはずなので、そのタイミングで A に移す（カードの中身をそのまま
下位タブへ移すだけなので、作り直しにはならない）。

### 畳み方は、すでにある形をそのまま使う

調整ローテの「開始時点の内部数値 / エサの効き方」と同じ作りにする
（`js/simulator/rotation.js` の `setupSection()`）。

- 見出しボタンに `▼ / ▶` を付け、`aria-expanded` と `aria-controls` を持たせる
- 開いたかどうかは **`state.ui` に覚える**（`gridOpen` / `rotaOpen` と同じ持ち方。
  たとえば `movesOpen`）。`state.ui` は既定値を足すだけなので、旧データの移行は要らない
- 中身は開くまで描かない（＝そこで初めて `moves.js` を取りに行く。下記4）

### 画面（実装ずみ）

```
（使い込みの表・履歴・メモ …）

  ▼ この種族が覚える技  全21技       ← たたんだカード。押すと開く
  ┌────────────────────────────────────────────┐
  │ (G) (ダメ) (命) (GD) (CR) (時間)             │  ← 押した列で並べ替え
  │ 技名     種類    距離 消費G ダメージ 命中 … 備考 │
  │ タッチ   バランス  1   12   E(6)  A(10) … —   │
  │ はり手   バランス  1   18   D(15) A(9)  … タッチ30回│
  └────────────────────────────────────────────┘
```

- 表は `class="table"` を `.scroll-x` で包む（使い込みの表と同じ作り）。
  15列あるので、**技名の列だけ `position:sticky` で左に貼り付けてある**
- 技名のセルは **@wiki と同じ黄 / 緑**で塗る（黄＝ちから技 / 緑＝かしこさ技）。
  色の意味は画面には書かない
- ダメージ / 命中 / GD / CR は `E(6)` の形のバッジにして、**@wiki と同じ色分け**にした
- **並べ替え**は `G / ダメ / 命 / GD / CR / 時間` の6つ。押すたびに
  「押していない → その列で並べ替え → 逆順 → 表のままに戻る」と変わる
  - はじめの向きは列ごとに変えてある。ダメージ・命中・GD・CR は
    **大きいほど強い**ので大きい順から、消費ガッツと当時間は
    **小さいほど良い**ので小さい順から始まる
  - 空欄（`—`）の技は、どちらの向きでも必ずいちばん下に置く
  - 同じ値どうしは @wiki の表の並びのまま（JS の `sort` は安定なので、そのままで保たれる）
  - 並べ替えた状態は保存しない（開閉だけ覚える）
- 使い込み技がない3種族（ライガー / スエゾー / ジョーカー）でも、このカードは中身が出る
- 空欄は `—`。備考は表の文章をそのまま出す

### 種族の名簿について

いま名簿は `MONSTER_DATA` から作っている。`moves.js` を足しても**当面はそのまま**でよい
（38種は両方に載るので）。派生種を足すとき（`docs/roadmap.md` ①）に名簿を切り離す話が
出てくるので、そのときまとめて直す。ここでは触らない。

## 4. 読み込み方

ざっくりの見積り：**38種 × 10〜20技 ≒ 400〜500技**、1技あたり100バイト前後で **50KB前後**。
アイコン（`js/data/icons.js`、40KB）と同じくらい。

なので **アイコンと同じ遅延読み込み**にする。

```js
// 技一覧を最初に開いたときだけ取りに行く
import('../data/moves.js').then((m) => m.MOVES)
```

起動が重くならないし、技一覧を見ない人は読み込まない。
`js/species.js` の `loadIcons()` がそのまま手本になる。

## 6. 進め方

| 段階 | 中身 | 分量 |
|---|---|---|
| ①**済** | 形を決めて、**1種族ぶん（ピクシー）だけ**入れて画面とテストを通す | 小 |
| ② | 残り37種を **1種族ずつ**足す（`SPECIES_SPEC` と同じやり方。1コミット1種族） | 大。データ次第 |
| ③ | 習得条件（`req`）を足して、届かない技をグレーにする | 中 |
| ④ | 技を選ぶ → 育成計画へ（修行回数・目標ステータス・ヨイワルの順番） | 別の検討 |

**①をやってから②に入る**のが大事で、形が決まる前に400技を入れると、
列を足すたびに全部書き直すことになる。

①は @wiki のピクシーの表をもらった時点で済ませた。列も確定している。
**②は、種族ぶんの表を1つずつ渡してもらうたびに足していく**（1コミット1種族）。

テストは `SPECIES_SPEC` と同じく **`MOVES` を読んで全種族ぶんを自動でまわす**ので、
種族を足すときにテストを書き足す必要はない。

## 7. データの集め方（ここが本番）

@wiki は**このリポジトリの実行環境からは取りに行けない**（ネットワークが塞がれている）ので、
**中身を渡してもらう**形になる。1種族ぶんずつ、下のどれかで貼ってもらえれば変換できる。

- @wiki の表をそのままコピペ（タブ区切りになる）
- 手打ちなら `技名 / 間合 / 消費G / ダメージ / 命中 / クリ / 覚え方` の順で1行1技

```
ピクシー
タッチ	1	12	30	20	5	最初から
はり手	1	18	45	10	5	使い込み タッチ 30
ヒールレイド	2	19	60	-5	10	修行 火山
```

**画像で貼ってもらうのがいちばん早い**（ピクシーぶんはそうやってもらった）。
表を読んで `js/data/moves.js` の形に起こす。写し間違いは、`monsters.js` と重なっている
4つの値（消費G・当時間・外時間・使い込み回数）の突き合わせで、かなりの割合が落ちる
— ピクシーでは8ペア×4＝32か所を自動照合できた。

## 9. ついでに見つけた不具合（別に直す）

`sw.js` の `ASSETS` に **`js/data/species-spec.js` が入っていない**。
`js/store.js` が静的 import しているので、初回からオフラインだと読み込めず起動しない
（1度オンラインで開けば `fetch` 側でキャッシュされるため、気づきにくい）。
**直しずみ**（`species-spec.js` を `ASSETS` に足して `CACHE_VERSION` を上げた）。
